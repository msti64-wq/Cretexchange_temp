# Product

## Purpose

This section documents product direction, user-facing priorities, and the decisions that shape CreteXchange.

## What Belongs Here

- Vision and mission notes
- Roadmap planning
- Product decisions and rationale
- Driver experience guidance
- Owner experience guidance
- Admin experience guidance
- Competitive advantages
- Backlog summaries
- Glossary and domain terms

## What Does Not Belong Here

- Technical architecture diagrams
- API endpoint documentation
- Design system rules
- Runtime code or implementation details
- Changelog entries or release logs

## Planned Contents

- Product vision and positioning
- Roadmap milestones and priority themes
- Experience strategy for drivers, owners, and admins
- Competitive differentiation notes
- Product glossary and shared terminology

## Maintenance Note

Keep product notes outcome-focused and user-facing. Record decisions here when they change how the product should behave or what users should expect.
