# Environment Variables Reference

## Required Secrets for CreteXchange

When setting up the duplicated app, configure these environment variables in Replit Secrets:

---

## 🔐 Column BaaS (Banking & Wallets)

```bash
COLUMN_API_KEY=test_33Hx8...
# Get from: https://column.com/dashboard

COLUMN_API_BASE_URL=https://api.column.com
# Fixed value - production endpoint

COLUMN_PLATFORM_ACCOUNT_ID=your_account_id_here
# Your Column platform account ID

COLUMN_PLATFORM_ACCOUNT_NUMBER=your_account_number_here
# Your Column platform account number

COLUMN_PLATFORM_ENTITY_ID=your_entity_id_here
# Your Column platform entity ID

COLUMN_PLATFORM_ROUTING=your_routing_number_here
# Your Column platform routing number
```

---

## 💳 Lithic (Debit Cards)

```bash
LITHIC_API_KEY=your_lithic_sandbox_key_here
# Get from: https://sandbox.lithic.com/dashboard

LITHIC_BASE_URL=https://sandbox.lithic.com/v1
# Sandbox endpoint (use https://api.lithic.com/v1 for production)

# Optional (for production only):
# LITHIC_CARD_PROGRAM_TOKEN=your_program_token
# LITHIC_PRODUCT_ID=your_product_id
```

---

## 💰 Stripe (Payments & Subscriptions)

```bash
STRIPE_SECRET_KEY=sk_test_...
# Get from: https://dashboard.stripe.com/test/apikeys

VITE_STRIPE_PUBLIC_KEY=pk_test_...
# Get from: https://dashboard.stripe.com/test/apikeys
# Note: Prefix with VITE_ for frontend access
```

---

## 🗄️ Database (Auto-generated)

```bash
DATABASE_URL=postgresql://user:password@host:port/database
# Automatically created when you create a Replit PostgreSQL database
# Don't manually set this - let Replit generate it
```

---

## 📝 Notes

### For Duplicated/Test App:
- Use **TEST** API keys (sk_test_, pk_test_)
- Use **SANDBOX** endpoints for Lithic
- Create a **NEW** database (don't reuse production DB)
- Keep test data separate from production

### For Production App:
- Use **LIVE** API keys (sk_live_, pk_live_)  
- Use **PRODUCTION** endpoints
- Ensure Column BIN sponsorship is approved
- Use real Lithic card program tokens

---

## ⚠️ Security Best Practices

1. **Never commit secrets to git** - .gitignore already excludes .env files
2. **Use test keys for development** - Keep production keys secure
3. **Separate environments** - Different keys for dev/staging/production
4. **Rotate keys regularly** - Especially if exposed or compromised
5. **Minimum permissions** - Use restricted API keys when possible
