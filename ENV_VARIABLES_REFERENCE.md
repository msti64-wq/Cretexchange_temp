# Environment Variables Reference

## Required Secrets for CreteXchange

Configure these environment variables in the deployment platform secrets manager.
Use placeholder or test values only in local examples.

---

## Core Runtime

```bash
NODE_ENV=production
PORT=5000
# Railway/Render/Replit: HOST=0.0.0.0
# Local-only testing: HOST=127.0.0.1
HOST=0.0.0.0
DATABASE_URL=postgresql://user:password@host:5432/database
BASE_URL=https://your-production-domain.example
```

---

## Authentication

```bash
JWT_SECRET=replace-with-at-least-32-random-characters
SESSION_SECRET=replace-with-a-separate-long-random-session-secret
```

## Object Storage and Google Cloud

```bash

GOOGLE_CLOUD_BUCKET_NAME=your-gcs-bucket-name
DEFAULT_OBJECT_STORAGE_BUCKET_ID=your-object-storage-bucket-name
PRIVATE_OBJECT_DIR=/your-object-storage-bucket-name/private
PUBLIC_OBJECT_SEARCH_PATHS=/your-object-storage-bucket-name/public,/your-object-storage-bucket-name/uploads
VITE_GOOGLE_MAPS_API_KEY=your-google-maps-api-key
```

---

## Notes

### For Duplicated/Test App

- Use test Stripe keys (`sk_test_`, `pk_test_`).
- Create a new database; do not reuse production data.
- Keep test secrets separate from production.

### For Production App

- Use live Stripe keys (`sk_live_`, `pk_live_`).
- Set `HOST=0.0.0.0` for Railway, Render, Replit, and container deployments.
- Set `HOST=127.0.0.1` only for local-only testing.
- Remove all placeholder values before deployment.

| Google Cloud | https://console.cloud.google.com | APIs & Services / Cloud Storage |

---

## Security Best Practices

1. Never commit secrets to git; `.gitignore` excludes local env files.
2. Use test keys for development and staging.
3. Keep separate secrets for dev, staging, and production.
4. Rotate keys regularly and immediately after exposure.
5. Use restricted API keys when possible.
